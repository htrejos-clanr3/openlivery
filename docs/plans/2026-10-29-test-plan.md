# Test plan before touching production again

## Gates, in order

| Gate | What runs | Blocks |
|---|---|---|
| G1 Unit | `pytest -q` in `apps/api` | Everything |
| G2 Types | `npx tsc --noEmit` and `npm run lint` in `apps/web` | Build |
| G3 Migration | `alembic upgrade head` against a **clone of production** | Any schema change |
| G4 Tenant isolation | API calls with agency A token against agency B resources must return 404 | Any new endpoint |
| G5 Smoke | `./scripts/verify_production.sh` | Deploy |
| G6 WhatsApp E2E | Send a real message, expect a stored conversation and a reply within 30 s | Go-live |
| G7 Rollback | Restore the previous image tag and the dump; site back in under 15 min | Any deploy |

## Non-negotiables learned the hard way

- Never deploy with `tar` over an existing tree: use a clean directory.
- Never `down` the stack before the new build has succeeded once locally.
- Never trust `docker compose up` output as proof: verify with G5 after.
- Never assume a table does not exist: read the production schema first.
- Take the dump **and verify it restores** before any schema change.

## Evidence to keep

`docs/qa/signoffs/<date>-<commit>.md` with the QA block, the dump path, and the
commands that were run.
