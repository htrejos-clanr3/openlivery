# Guided Meta setup: what we can automate and what we must ask for

The goal is a controlled wizard: we show the exact link and the exact value to
paste, the user pastes it, we validate immediately when possible, and whatever
cannot be validated ends in a final checklist with a fix instruction.

Fast Livery already has most of the machinery: Embedded Signup session and
completion, the OAuth callback, webhook registration by phone number, WABA
subscription, HMAC verification and a health/test pair of endpoints. This note
covers the guided layer on top of it.

## Automatable vs manual

| Step | Automatic | Manual |
|---|---|---|
| Create the Meta developer app | No | developers.facebook.com, app name and type |
| Add the WhatsApp product | Partly | One click in the app dashboard |
| Create WABA and register the number | **Yes**, Embedded Signup | Phone must receive SMS or voice code |
| Obtain the system token | **Yes**, code exchange | — |
| Register the webhook on the number | **Yes**, Graph call | — |
| Subscribe the app to the WABA | **Yes**, Graph call | — |
| Verify granted permissions | **Yes**, `debug_token` | — |
| Link the Instagram professional account | **Yes**, read Page → IG | Account must already exist |
| Domain verification | **Partly**, we generate the token and verify | DNS record or meta tag added by the client |
| Business verification | **No** | Documents, Meta review |
| App review for advanced permissions | **No** | Meta review |
| Payment method for messaging | **No** | Billing in Meta |

## Values we generate, and where they go

| Value | Generated by us | Pasted where |
|---|---|---|
| Webhook callback URL | `{public_url}/api/public/whatsapp-cloud/channels/{channel_id}/webhook` | App → WhatsApp → Configuration → Callback URL |
| Verify token | per channel, stored encrypted | same screen, "Verify token" |
| App secret | client or platform | App → Settings → Basic → App secret |
| App ID | client or platform | App → Settings → Basic |
| Embedded Signup config ID | platform setting | App → WhatsApp → Embedded Signup |
| OAuth redirect URI | `{public_url}/api/whatsapp-cloud/oauth/callback` | App → Facebook Login → Valid OAuth redirect URIs |
| Webhook fields | `messages` | App → WhatsApp → Configuration → Webhook fields |

## Steps, with the validation we run after each one

1. **App created.** No token yet: we only show the link and keep the step
   pending until credentials arrive.
2. **App ID and secret entered.** Validate `GET /{app_id}?fields=id,name` using
   `app_id|app_secret`. Fail → "App ID or secret do not match".
3. **WABA and phone number.** Embedded Signup returns `waba_id` and
   `phone_number_id`. Validate `GET /{phone_number_id}?fields=verified_name,
   display_phone_number,quality_rating`. Fail → token or IDs wrong.
4. **Webhook registered.** We call the register endpoint, then read
   `GET /{phone_number_id}?fields=webhook_configuration` and compare the
   callback URI with ours. Fail → missing `whatsapp_business_management`.
5. **App subscribed to the WABA.** `POST /{waba_id}/subscribed_apps`, then read
   `GET /{waba_id}/subscribed_apps` and look for our app. Fail → permission.
6. **Permissions.** `GET /debug_token?input_token=…` and compare granted scopes
   against the required set. Fail → list exactly which scope is missing and
   where to request it.
7. **Instagram link.** `GET /{page_id}?fields=instagram_business_account`. Fail
   → "the Page has no professional Instagram account linked".
8. **Domain verification.** We generate the token, the user adds the TXT record,
   we re-check. Fail → show the record again and the propagation note.
9. **Business verification.** Read `verification_status`; there is nothing to
   automate, so we show the status and the link.
10. **Final checklist and test message.** Run every check in one pass, show a
    green/amber/red list, and send a test message through our own endpoint.

## Failure to instruction, one to one

| Symptom | Instruction |
|---|---|
| `Invalid OAuth access token` | Regenerate the system user token and paste it again |
| `(#200) Requires whatsapp_business_management` | Add the permission to the system user and regenerate the token |
| Webhook verification failed | Verify token in Meta must equal the one shown here, character by character |
| No webhook deliveries | Check the callback URL ends in the channel id and that the app is subscribed |
| `Template not found` | Create the template in WhatsApp Manager; there is no API shortcut |
| Instagram account not found | Convert to professional and link it to the Page |

## UI

One screen, ten steps, each with: the exact link, the value to copy, a "Paste"
field, a "Validate" button and a result line. Steps that cannot be validated
show "pendiente de revisión de Meta" instead of pretending to pass. The final
state is the checklist, not a single green button.

## What we do not promise

We cannot skip Meta's business verification, app review, billing or the country
availability of any product. The wizard's value is telling the user exactly what
is missing and why, not pretending those gates do not exist.
